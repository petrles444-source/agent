X-Agent-Token: зачем нужен и как работает

  1. Что это. Пароль к серверу на Colab. Адрес туннеля (https://…trycloudflare.com) открытый и случайный: любой, кто его узнает, сможет бесплатно пользоваться твоей моделью. Токен доказывает, что запрос пришёл с твоего компьютера.
  2. Как устроен путь. Colab (ячейка D) печатает THINKING_TOKEN → ты один раз выполняешь python tools/thinking_cli.py set-url <URL> <TOKEN> → значение лежит в config/thinking.local.json → панель сама подставляет его в каждый запрос заголовком X-Agent-Token. Сервер на Colab сверяет и отвечает 401 «неверный токен», если не совпал.
  3. Автоматический режим (по умолчанию). Поле заполняется само из конфига при загрузке страницы — вводить ничего не нужно. Страница слушает только 127.0.0.1, поэтому токен виден только тебе.
  4. Когда вводить руками. Только после перезапуска Colab с новым токеном: скопируй THINKING_TOKEN из вывода ячейки D, вставь в поле и нажми «Сохранить» — значение запишется в конфиг (этот же результат даёт команда set-url).
  5. Если нет связи. python tools/thinking_cli.py doctor покажет TOKEN: задан/НЕ задан и причину обрыва; частая причина «401» — устаревший токен после перезапуска Colab.

Подробные отчёты субагента: цель, обоснование, шаги с ожидаемыми результатами, критерии успеха и найденные противоречия. Субагент не управляет системой и не правит файлы — он только советует. Сюда же падают отчёты рефлексии по метрикам (вкладка «Выгода»).

Чего он не делает

  • Не запускает и не останавливает работу: при падении Colab агент продолжает выполнять задачи по шаблону-заглушке.
  • Не пишет файлы игры и не рисует картинки — у него нет инструментов и доступа к API изображений. Файлы в dev_sandbox/ меняет только по кнопке «Применить» в режиме «Разработка».
  • Не планирует за агента в офлайне: заглушка отдаёт общую структуру, но решение принимаю я.
  • Не видит секретов: токены и пароли вычищаются до отправки (проверка has_secret).

Когда ускорение реально

  • Параллельная подготовка плана, пока я правлю другой файл: вызов уходит в фон и не блокирует работу.
  • Повторное использование готовой структуры: шаги, ожидаемые артефакты и критерии уже сформулированы — не тратится контекст на перечисление.
  • Второе мнение после неудачи: рефлексия подсказывает, что чинить дальше, вместо слепого повтора прогона.
  • Синхронный запрос (без --async/--stream в фоне) — это пауза, а не ускорение: средняя цифра видна в блоке выше.

Только технические события и команды: мысли субагента, переключения моделей, ошибки, итоги. Обращения — во вкладке «Связь агентов», изменения файлов — в «Разработка».
