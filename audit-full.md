## 2. Находки уровня A (критично)

### A-1. `Origin: null` обходит единственную CSRF-защиту панели → стирание журналов и запись файлов
`tools/thinking_cli.py:828` + `:963–976` + `thinking/client.py:1771`

Цепочка (каждое звено проверено по коду):
1. `host_allowed`: `if not origin or origin.lower() in ("null", "undefined"): return True` —
   literal `Origin: null` считается «curl без Origin»;
2. `_body()` не проверяет `Content-Type` — любое тело либо парсится как JSON, либо
   **молча превращается в `{}`**;
3. `delete_history` при пустом теле: `rid` нет, `n is None`, `before == ""` → ветка
   `else: hit = True` → **файл журнала переписывается пустым**.

Итог: страница злоумышленника в sandboxed-iframe / `data:` / `file:` шлёт POST
`http://127.0.0.1:8765/api/delete` с `Origin: null` — `Host` локальный (проходит),
`Origin` считается своим (проходит) → `reports.jsonl` стёрт. Через `enctype="text/plain"`
форма даёт валидный JSON → стираются все три журнала. Дальше — `/api/dev/file`
(запись произвольного файла в рабочую папку) и `/api/dev/run` (запуск `.py`),
`/api/token` (подмена токена), `/api/memory` (импорт памяти).

Проверки Host от DNS-rebinding это не спасает — она всегда видит локальный хост;
единственная CSRF-защита здесь как раз Origin.

**Закрепляет дыру собственный тест** `tools/thinking_test.py:2162–2163`:
`check(mod.host_allowed("127.0.0.1:8765", "null", 8765), "…запрос без Origin (curl, file://) не блокируется)`.

**Фикс:** (1) `host_allowed` → при `origin.lower() in ("null", "undefined")` возвращать
`False` (пустой Origin оставить — curl); (2) `_body()` требовать
`Content-Type: application/json`, иначе 400; (3) `/api/delete` → 400, если не задано ни
`rid`, ни `n`+`at`, ни `before`; (4) переписать тест на `is False`;
(5) в `_send` добавить `X-Frame-Options: DENY` + `frame-ancestors 'none'` (обход
Origin силами пользователя через кликабельный iframe — [02](audit-full/02-cli-panel.md), B-уровень).

### A-2. Серверный `redact()` не получил правку B-1 — JSON-секреты уезжают в Colab и в дамп
`thinking/colab/cell_c_server.py:74–76, 83–84` (использование: `:148, 193, 245, 434, 440, 873–874`)

Воспроизведено на одном входе:

| Вход | `schemas.redact_secrets` | серверный `redact()` |
|---|---|---|
| `{"password": "hunter2"}` | `{"password=[скрыто]"}` | **без изменений** |
| `{"token": "kJC-…NqJ", …}` | маскируется | **без изменений** |
| `password=hunter2` | маскируется | маскируется |
| `token = os.getenv("X")` | оставлено (AUD-13, **так и задумано**) | `token=[скрыто]` — искажает текст |

Паттерн в ячейке C остался старым (`\s*[=:]\s*\S+`), в `schemas.py:42–46` он уже
`["']?\s*[=:]\s*["']?…` + исключение ссылок `_SECRET_REF`. Через `emit()` (`:245`) сырые
секреты попадают в шину событий, `/events`, снапшот cell E и `last_bad_json.txt`
(`:562–567`, пишется вообще без `redact`) → `GET /dump/…` наружу.

**Фикс:** перенести в ячейку C паттерн + `_SECRET_REF`/`_secret_rhs` из `schemas.py`
(лучше — импортировать общий модуль из zip) + тест-маркер «серверный SECRET_RE идентичен
`schemas`» рядом с существующим тестом на `redact_secrets`.

### A-3. `_json` не оборачивает чтение тела ответа
`thinking/client.py:389–396`

`raw = resp.read()` стоит вне `try`: `socket.timeout`, `http.client.IncompleteRead`
(**не наследует OSError**), `ConnectionResetError` вылетают сырыми, не поставив
`last_error`/предохранитель. `chat()` (`:1130`), `models()`, `/api/chat` панели
(`thinking_cli.py:1017`) ловят только `ThinkingError` → исключение уходит из `do_POST`
без outer-try → `BaseHTTPRequestHandler` роняет соединение **без ответа**, фетч панели
получает network error, офлайн-заглушка чата не срабатывает. Это ровно тот сценарий
(обрыв тела посреди ответа), ради которого тут и живёт туннель.

**Фикс:** обернуть чтение в `try/except (socket.timeout, http.client.HTTPException,
OSError) as exc: raise ThinkingError(f"обрыв чтения ответа: {exc}") from exc`.

## 3. Находки уровня B, сгруппированные по темам

### Устойчивость транспорта и предохранители (`client.py`)
- Провал `plan_stream` не пишется ни в журнал, ни в `stats["errors"]` — при мёртвом
  туннеле в «Диагностике» ноль ошибок (`:461–503`, `:700–706`).
- `_is_read_timeout` решает по подстроке: `сервер: … ReadTimeout` принимается за мёртвый
  транспорт → не-потоковый `/plan` пропускается, лог врёт (`:114–126`). У `chat_stream`
  и `reflect` префикс `"сервер:"` исключается корректно — обработка непоследовательна.
- Предохранители не сбрасываются при смене адреса: `set-url` на свежий туннель блокируется
  до 600 с чужими ошибками (`:316–322`).
- После истечения паузы счётчик не обнуляется → 1 ошибка снова открывает гейт на 600 с,
  «5 ошибок подряд» превращается в «1 ошибка раз в 10 минут» (`:316–386`).
- `set-url` не переподключает живой SSE — split-brain «REST новый / события старые» (`:741–775`).
- `plan_stream(remember=True)` пишет **каждый** токен в `thoughts.jsonl` (сервер не ставит
  `seq` → дедуп не работает) — сотни строк на один план (`:489–492`).
- Метрика «в фоне» никогда не может быть ненулевой — никто не передаёт `background=True`,
  `_record_chat` хардкодит `False`, а правило `reflect_metrics` сравнивается с единицей (`:891–910`).
- Три разные семантики «ошибки» в чате → `stats["errors"]` занижается на два из трёх путей (`:1156–1174`).
- `clearAll`/`clearOld` воскрешают записи: фильтр `self.reports`/`self.interactions`
  стоит только под `if rid:` (`:1780–1783`).
- Кнопка «только заглушки» ничего не удаляет: панель шлёт `{kind, n}` без `at`/`rid`,
  а сервер требует совпадения `n` **и** `at` (`html:987` ↔ `client.py:1765`).

### Ресурсы и производительность

  под пинги — **самое правдоподобное объяснение, почему повторы не помогают** (`cell_c:456, 812, 921`).

  каждый запуск ячейки D (`cell_d:355`).

  `llm2/llm3`, а `/parallel` читает устаревший манифест (`cell_c:1123`).
- Сторож трактует 401/429 как «API лёг» и перезапускает здоровый процесс; умерший
