# Отчёт полного код-аудита: `tools/thinking_cli.py` + `tools/thinking_panel.html`

## Краткая оценка

Оба файла прочитаны целиком (~3 500 строк), контракты сверены с `thinking/client.py`, `cell_c_server.py` и `thinking_test.py`. Фиксы из прошлых аудитов проверены и в целом корректны: AUD-01 (`utcnow` импортирован), AUD-02 (`devConfirmAnswer` берёт `p.filename/p.code`), AUD-03 (`--async` через отсоединённый процесс), AUD-15 (`renderMemory` под сигнатурой), AUD-17 (`host_allowed` покрывает все маршруты, обходов нет), AUD-18, AUD-23, B-6, B-8, C-3, C-8, N-4 — закрыты; XSS через `innerHTML` не найден (все вставки через `textContent`/`createTextNode`), CORS-заголовков нет (правильно), путь к статике захардкожен (traversal невозможен). Однако **гейт Origin имеет дыру уровня A** (literal `Origin: null` считается «не-браузером», а не-JSON тела молча превращаются в `{}`), из-за чего кросс-сайтовый CSRF стирает журналы; плюс несколько молчаливо сломанных функций (`clearFallback`, `ask --json`, потерянные несохранённые правки в «Разработке») и ресурсные вопросы (полный парс `chat.jsonl` до 8 МБ каждые 2,5 с, `devlog.jsonl` без ротации).

## Находки

### A — критично

**[A] tools/thinking_cli.py:828 + :963–976 + :1102–1118 — CSRF через `Origin: null`: любой веб-сайт стирает журналы панели.** `host_allowed` считает `Origin: null`/`undefined` отсутствием Origin и возвращает `True` (cli:828–829), а `_body()` не проверяет Content-Type — form-urlencoded тело не парсится как JSON и **молча превращается в `{}`** (cli:971–976). Цепочка: страница злоумышленника встраивает `<iframe sandbox="allow-forms" srcdoc="…form method=POST action=http://127.0.0.1:8765/api/delete…">` → браузер шлёт `Host: 127.0.0.1:8765` (локальный → проходит) + `Origin: null` (проходит) → тело `kind=report` → `{}` → `delete_history(kind="report", n=None, before="")` → ветка `hit = True` (client.py:1771–1772) → **весь `reports.jsonl` стирается без подтверждения**. Form с `enctype="text/plain"` даёт валидный JSON (шов `=` прячется внутрь строки: `{"kind":"all","x":"` + `=` + `"}`) → стираются все три журнала; `/api/reflect-metrics` с `{}` запускает реальную рефлексию; `/api/token` с тем же трюком портит токен. Тест `thinking_test.py:2162–2163` **закрепляет уязвимость** («file:// не блокируется» — но file:/sandboxed-запросы к панели и есть атака; curl даёт *пустой* Origin, а не `null`). Почему важно: Host-проверка от DNS-rebinding не спасает — она всегда видит локальный хост, единственная CSRF-защита — Origin. Фикс: (1) в `host_allowed` literal `"null"`/`"undefined"` → `return False` (пустой Origin оставить — curl); (2) в `_body()` требовать `Content-Type: application/json` → иначе 400; (3) переписать тест на `host_allowed(..., "null", 8765) is False`.

### B — важно

**[B] tools/thinking_panel.html:987 — кнопка «только заглушки» не удаляет ничего.** `clearFallback` шлёт `api("/api/delete", {kind:"report", n: n})` без `rid` и `at`, а сервер требует совпадения `n` **и** `at` (client.py:1767–1768: `hit = (n == ... and str(line.at) == str(at))`, `at=""` никогда не совпадёт) → `removed: 0`, и ответ даже не читается. **[B] tools/thinking_cli.py:307–314 — `ask --json` (и `--files/--constraint/--context`) молча игнорируются.** `cmd_ask` принудительно делает `args.json = False`, обнуляет `files/constraint/context`, хотя парсер `ask` их принимает (cli:1413–1420). Фикс: при `args.json` диагностику и поток писать в `sys.stderr` (в `_plan_streamed` передавать флаг `quiet`).

**[B] tools/thinking_cli.py:1234–1240 → thinking/client.py:138–156, 1899 — `/api/state` парсит весь `chat.jsonl` (до 8 МБ) каждые 2,5 с.** `status()` вызывает `_read_jsonl(self._chat_path, 60)` **без** mtime-кэша (в отличие от `_load_history`), а `_read_jsonl` читает файл целиком и `json.loads`-ит каждую строку, отрезая хвост. **[B] thinking/client.py:1904 (отдаётся через cli:1239) — `/api/state` отдаёт `base` — URL туннеля Colab, вопреки требованию «URL не должен отдаваться из API».** JS использует его только для строки меты с обрезкой схемы (`html:1881`).
