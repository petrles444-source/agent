## 1. Зачем нужен проект (бизнес-/пользовательская ценность)

| Слой | Ценность |
|---|---|
| Инфраструктура мышления | Субагент-«второй мозг»: планирует задачу до выполнения, рефлексирует после, корректирует. Не «ещё один чат-бот», а отдельный мыслительный цикл с памятью и честными метриками (confidence, fallback-маркировка, `tokens_estimate`). |
| Стоимость | Ключевое конкурентное свойство: LLM-инференс на бесплатном Google Colab (T4, при 0 ₽/мес) через llama.cpp. PC-клиент — чистый stdlib Python: ноль зависимостей, ноль лицензий, встраивается куда угодно (скрипт, CI, другой агент). |
| Управляемость | Dev-режим: модель предлагает патчи к собственному промту/коду, человек применяет или откатывает, всё в журнале — готовый датасет для дообучения промптов. |
| Доверие | Честность как архитектура: локальный fallback при падении транспорта, метрики деградации, журналы с rid/seq, schema-снэпшот в CI. Для условий слабых моделей (Qwen 1.5–7B) — не опция, а requisito. |

Кто целевой пользователь: разработчик-одиночка / небольшая команда, которая хочет недорогого «прораба» по планированию задач и ревью собственных патчей без подписок на LLM-API. Проект — прототип встраиваемой мыслительной подсистемы (MCP/HTTP-обёртка уже в бэклоге ТЗ).

## 2. Коммерческий и технический потенциал

| Направление | Потенциал | Аргумент «зачем платят» |
|---|---|---|
| Встраиваемый субагент (SDK/HTTP/MCP) | Высокий | Один `plan`-вызов из любого агента/CI — чужие оркестраторы (LangGraph, DSH, Aider-подобные) получат планировщика дешевле API. |
| Self-hosted «второй мозг» для разработчиков | Средний | Бесплатная инфраструктура + локальная память = приватность без облака; монетизация через GUI/подписку. |
| Dev-режим как «A/B-лаборатория промптов» | Высокий (никша) | Журнал «предложение → принял/отклонил» — готовый датасет калибровки; аналоги (prompt-оптимизаторы) только платные API. |
| Монетизация | — | SaaS не нужен: модель бесплатная. Деньги — за управление (панель, мультипроектность, отчёты), не за инференс. Цемент: Calab лимиты (CPU 1–3 tok/s, ~120 s silent-kill туннеля) — без них UX плохой, т.е. платят за обвязку, которая делает бесплатную модель терпимой. |
| Технический апсайд | 3B→7B, T4, prefix-кэш системных промптов (система+память = до 50% промта), `n_ctx`-оптимизации — скорость вырастет в разы без роста затрат. | Мост к платным пользователям (локальная GPU, Kaggle 30 GPU-ч/нед) уже заложен: сервер отвязан от Colab. |

## 3. План 30 / 90 / 180 дней

### 30 дней — «закончи технические долги + сделай инфраструктуру надёжной»

| # | Действие | Откуда | Эффект |
|---|---|---|---|
| 1 | Закрыть AUD-09/10 (pid-based смена модели + сторож) | audit §11 | Colab живёт днями, не часами |
| 2 | AUD-17/21 (Host/Origin, маскировка токена, убрать CORS `*` + `?token=` в query) | audit §8 | Доволен всемирный аудит перед публикацией |
| 3 | AUD-16 (блокировки `delete_history`, `_write_memory`) + AUD-12 (`coerce_plan` сервером, не клиентом) | audit | Гонки памяти, кривые ответы 1.5B |
| 4 | Именованный туннель по умолчанию (`CLOUDFLARE_TUNNEL_TOKEN`) | ПЛАН_РАЗВИТИЯ §1 | Убивает класс «set-url после рестарта» |
| 5 | Поведенческие тесты панели (Playwright) + мок-стенд Colab (http.server) | audit §10.4–10.5 | Баги панели и транспорта ловятся локально, не в бою |
| 6 | Мелочи AUD-19/20 (422 → «Colab down», `compare_digest`, mёртвый код) | audit §11 | Чистота |

### 90 дней — «сделай продукт, а не прототип»

| # | Действие | Эффект |
|---|---|---|
| 1 | Uскорение: T4 по умолчанию, prefix-кэш llama.cpp, `--threads` под 2 ядра, `--cache-reuse` | TTFT 60–80 c → десятки секунд, модель перестаёт «молчать» на длинных ответах |
| 2 | Мультипроектность памяти (`memory/<project>.json` + селектор в панели) | Продукт для команд, не для одного проекта |
| 3 | Векторный поиск по истории диалогов (эмбеддинги на стороне Colab) | «Второй мозг» реально запоминает |
| 4 | MCP/HTTP-обёртка: субагент как ресурс для чужих агентов одной командой | Ключевой шаг к «встраиваемой подсистеме» из ТЗ |
| 5 | best-of-N альтернативные планы + калибровка `confidence` по исторической точности (данные уже копятся в `reports.jsonl`) | Параметр confidence перестаёт быть «на глаз» |
| 6 | Отчёты: недельный/месячный экспорт (есть суточный) | Витрина для монетизации |

### 180 дней — «рынок и масштаб»

| # | Действие | Эффект |
|---|---|---|
| 1 | Перенос рантайма: Kaggle 30 GPU-ч/нед или мини-ПК → Colab остаётся dev-режимом | Скорость на порядок выше, без Calab-лимитов |
| 2 | Иерархия субагентов: планировщик → исполнитель → критик на одном движке | От одиночного агента к оркестратору |
| 3 | Классификатор «чат/план/код» на входе панели (компактная модель) | UX: человек не выбирает вкладку сам |
| 4 | Платная подписка: GUI + мультипроектность + отчёты + «облако» (если нужен) | Первый доход: модель бесплатная, подписка за управление |
| 5 | Open-source community (репозиторий + CONTRIBUTING + образ Docker с сервером) | Канал найма и обратная связь |

## 4. Возможности, которые это открывает

| Область | Что открывается |
|---|---|
| Автоматизация | `plan`/`reflect` в CI: гит-хук «план → подтверждение → dev» на каждый пулл-реквест; автономный цикл «задача → план → код → критик → правка». |
| Модели | Один сервер — любая модель (swap по API без рестарта клиента); uncensored-теги уже в dev; дальше — MoE 3B/7B, Qwen 3, локальный Q4 для CPU-режима. |
| Интеграции | MCP-обёртка → IDE-агенты (DSH, Aider, Cursor); вебхук «рефлексия показала adj/abort → уведомление в чат»; экспорт планов в Notion/Jira. |
| UX | Панель: live-разбор токенов (уже есть), «что модель думает» (seq-журнал), A/B двух моделей в одном чате (best-of-N), аудио-режим (TTS ответа). |
| Монетизация | a) Подписка за GUI/мультипроектность; b) embed-SDK «1 вызов = 1 $/месяц»; c) white-label для команд (брендированная панель). Инференс остаётся бесплатным — маржа почти чистая. |
| Расширения | Мультипроектность памяти → «портфель проектов»; векторный поиск → «введение по истории»; иерархия субагентов → «отдел» агентов (архитектор/ревьюер/тестировщик). |

## 5. Риски и препятствия

| Риск | Вероятность | Митигция |
|---|---|---|
| Colab: silent-kill ~120 s, CPU-режим 1–3 tok/s, лимит 12 ч/день | Высокая (уже есть) | Именованный туннель + всемирный keepalive + SSE-ретрай (есть); дальше Kaggle/локальный GPU; CPU-режим — только fallback. |
| Слабые модели ломают JSON/семантику (plan_work_first: выдуманная зависимость, кривой `fallback`) | Высокая | `coerce_plan`/`guard_reply` (есть, усилить на сервере — AUD-12), schema-снэпшот, best-of-N, дообучение SYSTEM_DEV на журнале. |
| Безопасность: токен в query-string, CORS `*`, без Host/Origin, `/api/dev/run` = выполнение кода | Средняя | AUD-17/21 (30 дней); пока локальная сеть + NAT — не критично. |
| Зависимость от Cloudflare quick tunnel | Средняя | Именованный туннель (30 дней); в 180 дней — self-hosted (DoH/ssh-туннель/Tailscale). |
| Гонки в памяти (AUD-16), расхождение метрик | Средняя | Блокировки + один процесс записи; сверка журналов делается тестом (`tools/thinking_test.py`, поведенческие проверки записей и учёта). |
| Технический долг тестов: «строка есть в файле» пропускает регрессии | Высокая (уже есть) | Мутационное тестирование + Playwright + Hypothesis на парсерах (audit §10); цикл «баг → регресс-тест → фикс → CHANGELOG» уже доказан. |
| Scale: мультипользовательская подписка упрёт в Calab-лимиты | Средняя | Runtim-перенос (180 дней), rate-limit по клиенту (AUD-14, 30 дней). |
| Правовой: uncensored-теги + публичный репозиторий | Низкая | Лицензия + явное позиционирование; Dev-режим только в песочнице (есть). |

## 6. Приоритеты (топ, по порядку)

| Приоритет | Что | Почему сначала | Стоимость |
|---|---|---|---|
| P0 | AUD-09/10 + AUD-17/21 (надёжность движка + безопасность) | Без этого всё остальное — не «показать миру» | 2–3 ч + 1–2 ч |
| P1 | Именованный туннель по умолчанию | Дешёвый фикс, убирает класс инцидентов | 30 мин |
| P2 | Поведенческие тесты панели + мок-стенд | Фундамент для всех 90-дневных фич | 1 неделя |
| P3 | Uскорение (T4 + prefix-кэш + `--threads`) | UX-цемент, без которого ни подписки, ни CI | 2–3 дня |
| P4 | Мультипроектность + MCP/HTTP-обёртка | Продукт → встраиваемая подсистема, ключ к монетизации | 2–3 недели |
| P5 | best-of-N + калибровка confidence + дообучение SYSTEM_DEV | Конкурентное преимущество в нише «дешёвый разумный субагент» | 2–3 недели |
| P6 | Перенос рантайма (Kaggle/мини-ПК) | Убивает Calab-лимиты, открывает платный segment | 1–2 месяца |
| P7 | Подписка/GUI/white-label | Монетизация, только после P0–P5 | 2–3 месяца |

Итого: 30 дней — reliability + security + test-фундамент; 90 дней — продукт (мультипроектность, встраиваемость, скорость); 180 дней — рынок (self-hosted, иерархия агентов, подписка). Модель бесплатная, PC-стек stdlib, честность встроена — это уже реальный актив; остаток работы — инфраструктурный, не архитектурный.
