### Приоритет 1 — AUD-17: защита панели от DNS-rebinding

Панель слушает `127.0.0.1:8765` и умеет **писать и запускать код**. Страница
злоумышленника, резолвящаяся в 127.0.0.1, обходит same-origin и получает
выполнение Python на машине. Сейчас `Host` не проверяется.

- [ ] Проверка `Host` в `do_GET`/`do_POST` (только `127.0.0.1:<port>` и
      `localhost:<port>`), иначе 403 — отдельным методом `_deny_host()`
- [ ] Проверка `Origin` для POST (страховка от CSRF-форм)
- [ ] Не отдавать `token` в `/api/state` открытым — маска либо только по
      запросу из панели
- [ ] Тест: запрос с чужим `Host` → 403; с правильным → 200
- [ ] Живая проверка: `curl -H "Host: evil.example" http://127.0.0.1:8765/api/state` → 403

### Приоритет 2 — живой пробел: 524 на не-потоковом `/plan`

Замерено сегодня: 3B на CPU отдаёт план за ~180 с, Cloudflare обрывает
не-потоковый POST на 120 с. Потоковый `plan_stream` проходит (179 с).
Значит `plan()` через API на медленной модели **не работает вовсе**, и
`plan_timeout: 360` в конфиге сейчас вводит в заблуждение.

- [ ] Понятная диагностика: при 524 говорить «Cloudflare рвёт не-потоковый
      ответ, нужен поток», а не «Colab не отвечает»
- [ ] Решить, что делать с не-потоковым маршрутом: оставить только для
      быстрых моделей (1.5B) или отдавать 424 с объяснением
- [ ] Проверка: `doctor` и лог показывают разницу «поток»/«не-поток»

### Приоритет 3 — SSE keep-alive на сервере (давно висит в бэклоге)
