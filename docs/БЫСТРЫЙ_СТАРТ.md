# Быстрый старт субагента «Мышление» — инструкция на 2 минуты

Цель: запустить субагента (LLM на Colab) и подключить к нему ПК-панель.
Порядок всегда один: **Colab → две строки в ПК**.

---

## 1. Colab: открыть и запустить (≈5–10 минут)

Ячейка A делает ровно три вещи: ставит зависимости, ставит готовое колесо
движка (без компиляции) и кладёт модель. Если модель уже лежит на диске —
загрузка пропускается целиком, повторный запуск занимает секунды.

1. Открой <https://colab.research.google.com/drive>
2. Перетащи файл `colab/thinking_agent_ver3.ipynb` в окно Drive (или
   **Upload notebook → Upload → перетащи файл**). Актуальная сборка —
   `ver3`: режим «Разработка», рефлексия по метрикам, подсказки CPU/T4,
   все модели Qwen2.5 (1.5B/3B/7B и 7B без цензуры). Старая —
   `colab/thinking_colab.ipynb`.
3. Открой загруженный ноутбук → **Run all**.
4. Жди строку в выводе ячейки D:

```
================================================================
THINKING_URL= https://xxxx-xxxx.trycloudflare.com
THINKING_TOKEN= 0000000000000000000000000000000000
ТУННЕЛЬ: быстрый (случайный адрес)
================================================================
```

**Что означают строчки вывода (если что-то пошло не так):**

| Строки | Что делать |
|---|---|
| `GPU = True` | отлично, ответы 5–15 с |
| `GPU = False` | Colab дал CPU. Работать будет, но ответы 30–90 с. Смени тип среды: **Runtime → Change runtime type → T4 GPU** (если есть compute units) и снова Run all |
| `импорт после доустановки библиотек — ОК` | сработала починка CUDA-библиотек с PyPI, всё в порядке |
| `модель уже на диске — загрузка пропущена` | модель с прошлого раза на месте, качать не нужно |
| `…GGUF 1.91 ГБ за NNs` | модель скачалась |
| `не удалось поставить ни один движок LLM` | см. §5 «Если не запускается» |
| `LLM НЕ ПОДНЯЛСЯ` + последние строки лога | сервер не поднялся — открой `/content/llm.log` (см. §5) |

Модель выбирается сама, по возможностям рантайма: с GPU — 7B (быстрее отвечает),
без GPU — 3B (на CPU 7B считается очень долго), 1.5B остаётся запасной.
Качаются все четыре: 1.5B, 3B, 7B Instruct и 7B без цензуры — дальше их
переключают во вкладке «Модели». Для каждой модели ячейка A печатает
подсказку, какой режим ей нужен (CPU/T4). Если первая не скачалась —
берётся следующая, в выводе видно `(2/4: Qwen2.5-1.5B-Instruct-Q4_K_M.gguf)`.

## 2. ПК: подключиться (≈10 секунд)

```bash
cd ThinkingAgent
python tools/thinking_cli.py set-url <THINKING_URL> <THINKING_TOKEN>
python tools/thinking_cli.py doctor
```

Ожидаемый вывод doctor:

```
HEALTH:   ok
MODEL:    thinking  upstream=http://127.0.0.1:8001/v1/chat/completions
TOKEN:    задан
```

Адрес и токен сохраняются в `config/thinking.local.json` — вводить их второй
раз не нужно.

---

## 3. Панель

```bash
python tools/thinking_cli.py panel
```

→ <http://127.0.0.1:8765>

Вкладки: **Отчёты** · **Чат с субагентом** · **Разработка** (модель правит
файлы в `dev_sandbox/` только после вашего подтверждения: Применить /
Применить и запустить / Отмена, есть откаты и дамп) · **Модели** (переключение
+ подсказки CPU/T4) · **Диалог** · **Токены** · **Связь агентов** (что именно
уходило агенту и человеку) · **Выгода и ускорение** · **Журнал**.
Период по умолчанию «за сегодня», кнопка «за всё время» — в шапке.
У каждого отчёта и записи есть кнопка **удалить**.

Если порт занят — панель честно скажет и предложит `panel --port 8766`.

## 5. Если не запускается

| Симптом | Причина | Решение |
|---|---|---|
| `не удалось поставить ни один движок LLM` | нет сети до PyPI-колес или до Hugging Face | проверь сеть, запусти `Run all` ещё раз |
| `подтвердите, что не сбилось` в логе установки | оборвалась загрузка колеса | `Runtime → Restart runtime`, затем `Run all` |
| `LLM НЕ ПОДНЯЛСЯ` | модель не легла в память (обычно CPU и мало RAM) | `Run all` заново — ячейка D сама переберёт запасные модели; если опять нет, удали модель из `/content/models/llm` и запусти снова |
| `libcudart.so.12` | CUDA-библиотеки (лечится автоматически) | если осталось — `pip install nvidia-cuda-runtime-cu12` в отдельной ячейке |
| Быстрый адрес перестал работать через час | туннель Cloudflare одноразовый | `Run all` заново (или только ячейку D) → новый адрес → `set-url` |
| Хочется адрес, который не меняется | — | задай `CLOUDFLARE_TUNNEL_TOKEN` (см. README §4) |

Логи на Colab: `/content/llm.log` (движок LLM), `/content/thinking_api.log`
(наш сервер), `/content/tunnel.log` (туннель), `/content/last_bad_json.txt`
(неразобранный ответ модели).

Снять логи на ПК одной командой:

```bash
python tools/thinking_cli.py dump --all      # → colab_downloads/
```

## 6. Лимиты бесплатного Colab (важно: чётких квот нет)

Google не публикует точных квот — цифры в сообщениях Colab это ориентиры,
а не гарантия:

| Что видел Colab | Что это значит |
|---|---|
| GPU-сессия 2–4 часа (бывает до 12) | самый жёсткий лимит: бесплатный GPU отдают ненадолго. Сохраняй ноутбук заранее |
| «остаток ~28 ч» на CPU | расчётный остаток, не обещание: сессию могут прервать в любой момент |
| «закончились вычислительные единицы» | ты на бесплатном тарифе; доступ к ресурсам теперь зависит от нагрузки Google |

Как работать без паники:

1. **Дотяни на GPU** — пока он есть, гоняй 7B.
2. **Переходи на CPU** — в панели загорается предупреждение, берёшь 1.5B/3B
   (подсказки режима — во вкладке «Модели» и в выводе ячейки A).
3. **Если всё встало** — Colab: *Сессия → Лимиты*, чтобы понять причину.
   Лимиты обычно возвращаются примерно через сутки; иногда помогает пауза.
4. **Нужно прямо сейчас** — смена Google-аккаунта даёт «чистый лист»
   (Google отслеживает такие попытки, злоупотреблять не стоит).
5. **Запасные платформы**: Kaggle (~30 ч GPU в неделю), Paperspace Gradient,
   локальный runtime Colab.

Панель и `doctor` сами напоминают об этом: порог предупреждений — 2 ч на GPU
и около суток на CPU. На платные тарифы переходить не нужно — наше ПО
рассчитано на бесплатный Colab (потоковые эндпоинты уже обходят
120-секундный лимит туннеля).

## 7. Запуск «завтра» за 30 секунд (когда рантайм уже знакомый)

1. Открой тот же ноутбук в Colab → **Runtime → Restart runtime** →
   **Run all**.
2. Скопируй новые `THINKING_URL` и `THINKING_TOKEN`.
3. На ПК: `python tools/thinking_cli.py set-url <URL> <TOKEN>`.
4. `python tools/thinking_cli.py doctor` → `HEALTH: ok`.

Токен можно зафиксировать, чтобы ПК-конфиг не менялся: перед ячейкой D
выполни ячейку с `THINKING_TOKEN = "<токен из прошлого запуска>"` —
тогда меняется только адрес.
